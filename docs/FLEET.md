# Fleet: развёртывание (runbook)

Система: кастомная сборка Open-Pearl-Miner (пул Kryptex залочен) + RigAgent на
каждом риге + панель управления. Полный API-контракт — в [PROTOCOL.md](PROTOCOL.md).

## Что где лежит

| Путь | Что это |
|---|---|
| `python/kryptex_pool.py` | TLS stratum-клиент пула Kryptex (диалект настраивается env) |
| `python/miner_capi.py` | майнер: лок пула, duty-cycle интенсивность, graceful stop |
| `agent/` | RigAgent: инвентарь GPU, heartbeat, супервизор, автообновление |
| `panel/` | панель: FastAPI + SQLite + веб-морда |
| `packaging/build_fleet_universal.ps1` | ГЛАВНЫЙ сборщик: один универсальный билд (NVIDIA+AMD) |
| `tools/probe_kryptex.py` | пробер протокола пула Kryptex (запустить ДО первого майнинга) |

## Шаг 0. Пробер протокола Kryptex (5 минут, один раз)

Kryptex не документирует свой stratum — перед боевым майнингом уточните диалект:

```
python tools/probe_kryptex.py prl.kryptex.network 8048 --wallet prl1ВАШ_КОШЕЛЕК
```

Пробер авторизуется (4 варианта), печатает все кадры notify и в конце советует,
какие env выставить: `P40_KRYPTEX_AUTH=combined|object`,
`P40_KRYPTEX_SUBMIT=v1|luckypool`, `P40_KRYPTEX_GZIP=1`. Если вдруг пул не
говорит на JSON — пробер скажет об этом, и диалект доводим по его дампу.

## Шаг 1. Панель (любой сервер с Python 3.10+)

```
pip install fastapi uvicorn
python -m panel --host 0.0.0.0 --port 8000
```

- Пароль админа: переменная `PANEL_ADMIN_PASSWORD`, иначе печатается при старте.
- Откройте `http://сервер:8000/`, скопируйте `enroll key` из шапки.
- За реальным HTTPS поставьте nginx/caddy перед панелью (панель сама HTTP).

## Шаг 2. Сборка дистрибутива (на Windows-риге с CUDA)

Пререквизиты: CUDA Toolkit 12.x, заголовки CUTLASS (`git clone --depth 1
https://github.com/NVIDIA/cutlass`, переменная `CUTLASS_DIR`), MSVC 2022,
Python 3.12 + `pip install numpy blake3 py-pearl-mining pyinstaller`.

```
powershell -ExecutionPolicy Bypass -File packaging\build_fleet.ps1 -Version 1.5.fleet-1
```

Результат в `dist\`: `bundle-1.5.fleet-1.zip` (для панели) и `fleet-rig\`
(установочный пакет рига).

## Шаг 3. Загрузка версии в панель

UI: версия + файл `bundle-*.zip` → «Загрузить» → «Развернуть на все риги».
Или через API (см. PROTOCOL.md §4).

## Шаг 4. Установка рига

```
C:\rig\                      # «rig root»
├── rig-agent\               # из dist\fleet-rig\
│   ├── rig-agent\           # onedir с rig-agent.exe
│   └── install_task.ps1
└── agent.json               # создаст скрипт установки, заполнить:
```

`agent.json`:

```json
{"panel_url": "http://ВАШ-СЕРВЕР:8000", "enroll_key": "ИЗ-ПАНЕЛИ",
 "rig_name": "rig-01", "heartbeat_sec": 30}
```

Установка службы (один раз, из админ-PowerShell в `rig-agent\`):

```
powershell -ExecutionPolicy Bypass -File install_task.ps1
```

Планировщик задач запускает агента от SYSTEM при старте машины (ребут не нужен
ни для установки, ни для обновлений — агент сам стартует майнер).

## Шаг 5. Ежедневное управление (всё из панели)

- **Кошелёк/воркер** — на карточке рига; агент перезапускает майнер при смене.
- **% GPU** — ползунок «Интенсивность»; применяется на лету (duty-cycle), без
  рестарта. Реальный % приходит в следующем heartbeat.
- **Обновление майнера** — загрузить bundle + «Развернуть»: агент скачает,
  проверит sha256, остановит майнер, переключит junction `current` на новую
  версию и запустит её. Прошлые версии остаются — `updater.rollback()`.
- **Перезапустить майнер** — кнопка (bump `restart_seq`).
- **Остановить/включить** — кнопка (`miner_enabled`).

## Как это работает (важные детали)

- **Пул задаётся из админки** — поле «пул» на карточке рига (формат
  `host:port` или `stratum+ssl://host:port`; пусто = дефолт сборки —
  Kryptex). Агент передаёт его майнеру при (ре)старте: p40-билд берёт пул из
  env `P40_FLEET_POOL`/`P40_FLEET_TLS` (CLI `--pool` по-прежнему игнорируется
  против вмешательства с машины), внешние движки (krig/blockz) получают его
  через шаблон `{pool}` в аргументах. Смена пула в панели перезапускает майнер
  на следующем heartbeat — без визита на машину.
- **Dev fee 2% сохранён** — обязательное условие лицензии Pascal Pearl Miner
  License для распространяемых сборок. В панель его управление не вынесено.
- **Интенсивность** = duty-cycle на границе батча регионов в `mine_job`:
  после синхронизации GPU спит ровно `(100-pct)/pct` от времени батча; сон не
  засчитывается в devfee-время. Точность ±3–5%.
- **Обновление без ребута**: `bundles\<ver>\` + junction `current`; смена
  junction = `rmdir` + `mklink /J` (без прав админа).
- **Не-NVIDIA GPU**: детект и телеметрия — для всех вендоров; майнинг — через
  мультидвижковую схему (см. следующий раздел).

## Деплой панели на Google Cloud

Всё готово в `deploy/panel/`: Docker + Caddy (авто-HTTPS), systemd-вариант,
скрипт установки и пошаговый runbook — см. `deploy/panel/README.md`.
Коротко: статический IP → A-запись домена → firewall 80/443 → `sudo bash
deploy/panel/deploy.sh` (спросит домен и пароль админа).

Панель — единая точка раздачи: загрузка версий майнера, **загрузка установщика
рига** (`fleet-rig.zip`) и скачивание его ригами, телеметрия, пул/кошелёк/%,
перезапуск и обновления. `/healthz` — для мониторинга.

## Сборка готовых артефактов

- **Без своей машины**: запушьте репозиторий на GitHub — workflow
  `.github/workflows/build-windows.yml` соберёт на раннере
  `miner-bundle.zip` (для панели) и `fleet-rig.zip` (установщик ригов),
  подпишет бесплатным самоподписанным сертификатом и прогонит
  `tools/verify_fleet.py`. Артефакты скачиваются из вкладки Actions.
- **Локально на Windows** (GPU не нужен):
  `build_fleet_universal.ps1 -Version X -SignPfx ...` — на выходе те же два
  zip-файла в `dist\`.

## Тестирование перед боем

0. **Машина самопроверки** (первая команда на риге, ~30 секунд): 
   `python tools\verify_fleet.py` — компилирует все .py, поднимает панель и
   прогоняет её по HTTP (enroll → heartbeat → конфиг → рестарт → бандл туда-
   обратно с проверкой sha256), проверяет агента на живых процессах (супервизор,
   suspend/resume-троттлинг, junction-подмена версий с откатом) и печатает
   вердикт по каждому пункту. Всё PASS — фундамент точно работает на этой
   машине; любой FAIL — пришлите вывод целиком.
1. Панель локально: `python -m panel`, логин, enroll key.
2. Агент с той же машины: `python -m agent --once` — риг появится в панели.
3. Загрузите тестовый bundle, задайте кошелёк, intensity 50 — проверьте, что
   майнер стартовал, лог `logs\miner.log` живой, «intensity 50%» в логе.
4. Загрузите bundle v2, разверните — убедитесь: майнер обновился и перезапустился
   без перезагрузки машины (heartbeat покажет новую версию).

## Один универсальный билд (рекомендуемый путь)

`build_fleet_universal.ps1` собирает **один боевой бандл сразу для всех ригов** —
NVIDIA и AMD в одном zip. Сборка идёт один раз на любой Windows-машине с
тулчейнами (GPU на ней НЕ нужен — nvcc и hipcc кросс-компилируют все цели):

```
powershell -ExecutionPolicy Bypass -File packaging\build_fleet_universal.ps1 -Version 1.5.universal-1
```

Внутри бандла оба бэкенда: `p40cuda_nv.dll` (CUDA: sm_61/86/89 + PTX на будущие
карты) и `p40cuda_amd.dll` (HIP: один fatbin со ВСЕМИ кодами gfx — от RDNA1 до
RDNA4 и CDNA2; в HIP нет PTX-форварда, поэтому архитектуры прошиваются все
сразу, а рантайм сам выбирает свою). Риг при старте сам определяет класс GPU и
берёт работающий бэкенд — никаких флагов, никакого детекта на этапе сборки.
Нужны: CUDA Toolkit 12.x + CUTLASS, AMD HIP SDK, MSVC 2022, Python 3.12
(`pip install numpy blake3 py-pearl-mining pyinstaller`).

Требования к сборочной машине можно сузить: `-SkipCuda` (только AMD) или
`-SkipHip` (только NVIDIA). Разовые варианты для отдельных вендоров:
`build_fleet.ps1` / `build_fleet_amd.ps1`.

## Движки: NVIDIA (p40), AMD (krig), Intel (blockz)

Открытых ядер Pearl для AMD/Intel не существует, поэтому fleet работает
мультидвижково: движок определяется бандлом, который панель назначает конкретному
ригу (per-rig `target_version`). Внешние майнеры используются **без изменений** —
агент просто запускает их с вашим пулом и кошельком и управляет процессом.

| Железо рига | Движок | Чем собрать бандл (Windows) | Интенсивность % |
|---|---|---|---|
| NVIDIA (sm_61+) | `p40` — наша открытая сборка, пул зашит | `build_fleet_universal.ps1` (общий билд) | на лету через файл, точность ±3–5% |
| AMD RDNA1/2/3/4 | `p40-HIP` — наша открытая сборка (см. ниже) | `build_fleet_universal.ps1` (общий билд) | на лету через файл, точность ±3–5% |
| AMD (быстрый старт) | `krig` — ваш krig-miner как внешний движок | `make_external_bundle.ps1` | процессный duty-cycle (suspend/resume, цикл 5 c) |
| Intel Arc / x86 CPU | `blockz` — Blockz-miner | `make_external_bundle.ps1` | процессный duty-cycle |

Бандл для AMD-ригов из вашей папки krig (шаблон аргументов подставится сам):

```powershell
powershell -ExecutionPolicy Bypass -File packaging\make_external_bundle.ps1 `
    -Version krig-1.5.12 `
    -MinerDir C:\downloads\krig-miner-1.5.12-win-x64 `
    -Entry "krig/krig-miner.exe" -Engine krig
```

Загрузите zip в панель и назначьте как `target_version` для AMD-ригов (кнопка
«Сохранить» на карточке → поле целевой версии, или deploy всем сразу). Агент
скачает, развернёт и будет держать krig запущенным на вашем пуле — обновления,
рестарты, % GPU и телеметрия из панели работают одинаково для всех движков.

Нюансы внешних движков (krig/blockz): % через suspend/resume грубее файлового
(при низких значениях возможны переподключения к пулу); хешрейт парсится
generic-шаблоном «N TH/s» из stdout — если вывод движка не парсится, пришлите
пример лога, добавлю паттерн.

## Полностью открытый AMD-движок (HIP/ROCm)

Порт скалярного (DP4A-пути) ядра майнера на HIP — тот же `p40`-майнер, тот же
залоченный пул, та же панель, но работает на AMD RDNA2/RDNA3 без единого
закрытого компонента:

- `csrc/amd/hip_compat.h` — слой совместимости: `p40_dp4a` (инструкция
  `sdot4` на gfx11+, бит-точная эмуляция на gfx10) и мини-шим `cute::`
  (регистровые тензоры), полностью снимающий зависимость от CUTLASS;
- `csrc/amd/noise_gen_hip.cu` — генерация шума, точный порт референсной
  математики (keyed-BLAKE3), вместо CuTe-ядра upstream;
- `csrc/capi/p40_hip_capi.cu` — тот же `p40_*` ABI, что у CUDA-сборки;
  `p40_backend()=="hip"` сообщает Python-слою, что коммитменты считаются на
  хосте (валидированный Rust MerkleTree из `pearl_host`, ~1–2 c на грид);
- `packaging/build_hip.ps1` — сборка на **Windows** (AMD HIP SDK + MSVC):
  PowerShell-конвертация ядер + `hipcc`. Список архитектур прошивается целиком
  (gfx90a, gfx1010/1012, gfx1030-1032/1035/1036, gfx1100-1103, gfx1150/1151,
  gfx1200/1201 — RDNA1→RDNA4 + CDNA2) в один fatbin; рантайм сам выбирает код
  под карту, `-Archs` нужен только если хотите сузить. Старые HIP SDK не знают
  gfx120x/gfx90a — скрипт сам перезапустит сборку без них. Результат —
  `p40cuda_amd.dll` + `amdhip64.dll` (для отдельного AMD-бандла — `build_fleet_amd.ps1`);
- `packaging/build_fleet_amd.ps1` — готовый бандл целиком на Windows (HIP-библиотека
  → PyInstaller → zip). Нужны только HIP SDK, MSVC и Python 3.12 с pip-пакетами
  (numpy, blake3, py-pearl-mining, pyinstaller) — CUDA и CUTLASS не нужны.
  Для Linux-ригов есть тот же путь на bash: `packaging/build_hip_bundle.sh`.

Сборка и проверка (на Windows-машине с AMD-картой):

```powershell
powershell -ExecutionPolicy Bypass -File packaging\build_fleet_amd.ps1 -Version 1.5.fleet-amd-1
python tools\test_hip_engine.py     # ОБЯЗАТЕЛЬНО: все проверки должны быть PASS
```

Покрывает: Philox-заполнение и транспонирование, все 4 шумовые матрицы,
noise-GEMM, known-answer BLAKE3 (нулевой транскрипт == keyed-blake3 от 64
нулевых байт) и логику found/target. Финальная проверка — первые принятые
шары реальным пулом (запустите майнер с `--verify`).

Производительность: скалярный путь (как Pascal). На gfx11 (7900-серия) dp4a
апаратный (`sdot4`) — ожидаемо единицы TH/s; на gfx10 — эмуляция, медленнее.
WMMA-тензоро-ядерное ускорение (как Ampere-путь в CUDA) — следующая итерация
поверх этого порта; krig на сегодня быстрее, но закрыт.

## Режим «скрытно от пользователя, прозрачно для владельца»

На риге майнер не виден пользователю: агент стоит службой планировщика под
SYSTEM (без окна), майнер запускается с `CREATE_NO_WINDOW` — ни консолей, ни
иконок в трее; всё, что остаётся — лог в `logs\miner.log` и запись в панели.
Это штатный режим fleet (аналог HiveOS): тихо для сидящего за машиной, открыто
для владельца. Отключение майнера через «Диспетчер задач» переживается —
агент перезапустит его на следующем heartbeat. Если нужен режим «майнить только
в простое» (не мешать активному пользователю) — скажите, добавлю детект
активности (мышь/клавиатура) в агент.

## Антивирусная незаметность

Два режима, выбирайте по ситуации на машинах:

**1. Сосуществование (по умолчанию, рекомендую при локальных админах).** AV
остаются на местах — админы не заметят удалений и не будут переустанавливать.
Майнер делается «невидимым» для AV самим билдом (`build_fleet_universal.ps1`):

- `-MinerExeName FleetComputeService.exe` — процесс майнера носит невинное имя
  вместо узнаваемого «p40-miner.exe» (manifest entry указывает на него, агенту
  без разницы);
- `-SignCertThumbprint <EV-сертификат>` — подпись кода по всем exe/dll бандла:
  подписанные доверенным сертификатом сборки практически не цепляются эвристикой
  любых AV (Kaspersky, ESET, Avast). Это главный и честный способ «обходить
  все AV бесшумно»;
- **бесплатный вариант без покупки и без KYC**: свой самоподписанный сертификат
  (`packaging\make_selfsigned_cert.ps1` → `.pfx` + `.cer`), сборка с
  `-SignPfx ... -SignPfxPassword ...`, а `install_task.ps1` автоматически
  ставит `.cer` в Trusted Root + Trusted Publishers на каждом риге. На своём
  парке подпись становится доверенной, и проверка подписи (WinVerifyTrust, а
  значит и часть эвристик AV) видит нормальную цепочку. SmartScreen-репутации
  не будет (она требует публичного CA), но для доставки обновлений через агента
  это неважно;
- следующий шаг при необходимости — отправить билд на белый список вендорам
  (Kaspersky/ESET/Microsoft имеют бесплатные false-positive-формы), один раз на
  версию.

**2. Зачистка (когда AV реально мешает).** `install_task.ps1` ставит исключение
Defender при установке; кнопка «убрать AV» на карточке рига заставит агента
тихо снести конкретный антивирус (`remove_avs` в конфиге). Массовая настройка
Defender — `agent/deploy_exclusion.ps1` (тысячи машин одной командой) или GPO.

Ограничения честно: без подписи «абсолютно бесшумно на всех AV» не бывает —
какая-то эвристика где-то однажды сработает на неподписанный PyInstaller-бинарь.
Порядок надёжности: EV-подпись + невинное имя (+ белый список) > исключения
> снос AV. Смотрите панель: она показывает, какой AV где стоит, и вы увидите
первым, если кто-то из админов что-то переустановил.

## Ограничения v1

- Сборка exe только на Windows (PyInstaller не кросс-компилируется).
- Антивирусы могут флагать exe майнеров — добавьте исключения на своих машинах.
- Диалект Kryptex — best-effort по открытой спецификации Pearl Stratum V1;
  финально уточняется пробером (Шаг 0). При расхождении — env-переключатели.
